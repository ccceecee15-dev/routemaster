This is a follow-on change to the existing Route Master V2 screen.

IMPORTANT:
Only modify Route Master V2.
Do NOT modify the original Route Master.
Do NOT redesign the overall MerchX application.
Do NOT introduce backend/database/API work.

This is still a frontend-only prototype using mock data and frontend state.

We received additional client feedback during the latest Route Master review. The main change is that Route Master should be a RULE CONFIGURATION experience rather than a one-store-at-a-time route entry form.

==================================================
1. CORE BUSINESS MODEL
==================================================

The Route Master configuration should start with:

Vendor
+
Merchandise Area
+
Order Type

Then configure:

Delivery Calendar / Order Day

And based on Order Type:

DSD:
Vendor → Merchandise Area → Store

Warehouse BULK:
Vendor → Merchandise Area → Warehouse/Plant → Store

Lead Time and other route attributes are then managed for the resulting assignment.

The primary setup journey should therefore be:

Vendor
→ Merchandise Area
→ Order Type
→ Delivery Calendar
→ Warehouse/Plant OR Stores
→ Store assignments
→ Lead Time / Route details

==================================================
2. DO NOT USE STORE AS THE PRIMARY SETUP FILTER
==================================================

The client explicitly clarified that Vendor and Merchandise Area are the starting point.

The current top-level setup should NOT begin with:

Store
Store No.
Store Name

Instead, the first required selections should be:

1. Vendor
2. Merchandise Area
3. Order Type

Property, Format, Warehouse, and Store should be used to narrow the resulting assignments and make navigation easier.

Store remains extremely important, but it is the result of the selected routing rule rather than the primary rule definition.

==================================================
3. REDESIGN THE TOP OF ROUTE MASTER V2
==================================================

Keep the existing MerchX page structure, header, sidebar, breadcrumb, cards, filters and overall visual design.

However, introduce a prominent "Route Rule Configuration" area.

Use a clean horizontal or two-row configuration layout.

==================================================
23. MOST IMPORTANT UX PRINCIPLE
==================================================

The screen should communicate this workflow immediately:

1. WHO supplies it?
   → Vendor

2. WHAT merchandise does it apply to?
   → Merchandise Area

3. HOW is it ordered?
   → DSD or Warehouse BULK

4. WHEN is it ordered?
   → Delivery Calendar

5. WHERE does it flow?
   → Warehouse/Plant for BULK, Stores for DSD

6. WHICH stores are affected?
   → Store Assignment Table

7. WHAT is the lead time?
   → Lead Time (Weeks)

The user should NOT have to configure every store individually.

The main interaction is configuring a rule and applying it to a set of stores.
